# 高德周边地点推荐

使用平台已提供的高德 MCP，完成“找地点 → 从给定起点核验步行路线 → 筛选推荐”。本文件自包含；直接使用现有工具，无需安装依赖、申请 Key 或运行外部脚本。

## 1. 确定条件

- 读取城市、起点坐标及自然语言需求。坐标统一为 `经度,纬度`，保留用户给定起点，后续每条路线都从此处出发。
- 提取地点类别、步行时间上限、距离或搜索范围、数量及其他偏好。区分必须满足的条件和可用于排序的偏好；没有给出的限制不自行添加。
- 用户要求正整数 `N` 个时，输出上限为 `min(N, 3)`；没有指定数量时，上限为 3。上限不等于必须凑足的数量。
- 缺少城市、明确起点坐标，或关键条件存在会改变结果的歧义时，简短询问缺失项。起点不明确时，先取得明确坐标，再执行路线核验。

## 2. 搜索实际地点

先查看当前可用高德工具的名称、说明和输入 schema，按实际 schema 传参。常见工具如下；平台若增加名称前缀或调整字段，使用其对应能力与真实字段。

| 能力 | 常见工具 | 常见输入 |
| --- | --- | --- |
| 周边搜索 | `maps_around_search` | `location`、`keywords`、`radius` |
| 城市内关键词搜索 | `maps_text_search` | `keywords`、`city` |
| 地点详情 | `maps_search_detail` | `id` |
| 步行路线 | `maps_direction_walking` | `origin`、`destination` |

- 必须实际调用地点搜索。优先以原始起点作圆心进行周边搜索，关键词采用需求中可检索的类别或活动，如咖啡馆、公园。组合需求可分开检索相关类别，再合并候选。
- 周边搜索中的 `radius` 是候选检索半径，不是步行距离，也不能证明步行时间达标。按用户明确范围查询；未指定时从附近适度范围开始，候选不足再扩大合理范围或换用同义类别词。
- 只发送工具支持的参数，并遵守字段类型；部分 MCP 的 `radius` 要求字符串。关键词搜索支持城市参数时传入目标城市。排除城市或地址明显与目标冲突的结果，保留原始起点。
- 记录工具返回的 POI ID、名称、地址、坐标及可用属性，按 POI ID 去重。相同地点在多个搜索结果中出现只保留一次。
- 部分周边搜索结果只返回 ID、名称和地址，缺少坐标。此时先调用地点详情取得该 POI 的 `location`，再规划路线。无法取得唯一有效坐标的候选跳过；名称和地址也仅采用工具实际返回的信息。
- 先检查明显不符的类别或用户明确范围，再为有希望的候选规划路线。通常以 2–3 次有针对性的搜索、约 8–12 个候选的核验作为常规工作量；不足时围绕尚未覆盖的合理范围或类别补查。获得足够合格候选且无明显检索缺口，或补查已无新候选时停止，避免重复请求和无限扩搜。

## 3. 独立核验步行路线

每一个最终推荐地点，都必须有本次高德步行路线调用成功的证据：

1. `origin` 始终使用用户给定的同一原始起点，`destination` 使用当前候选的真实坐标。每个候选是独立目的地，不将上一个推荐点作为下一条路线的起点。
2. 调用步行路线能力，检查工具错误、业务失败和空路线。若结果以文本承载 JSON，读取其中实际返回的数据。
3. 常见结果是 `route.paths[]`，每条路线的 `distance` 单位为米，`duration` 单位为秒，数值可能是字符串。若当前工具明确采用 `cost.duration` 等结构，按其实际结构读取耗时。只采用完整路线的总距离、总耗时，保留两者来自同一条路线。
4. 多条有效步行方案时，优先取满足所有硬条件的方案，再以总耗时较短、总距离较短为顺序选择一条。将有限、非负的距离和耗时解析为数值；空值、错误值或缺失值不能当作 0。
5. 将用户的分钟上限 `T` 转为 `T * 60` 秒，以未取整的真实总耗时执行 `duration <= T * 60`。用户另有步行距离上限时，同样使用路线总距离核验。展示换算放在筛选之后，不能用取整后的分钟数放行超时路线。

路线失败、缺少有效总耗时或总距离的候选不进入已核验推荐。继续验证其他候选；必要时说明失败原因。搜索结果距离、直线测距和按步速估算都不能替代真实步行路线。

## 4. 排序与输出

- 先剔除违反明确硬条件的候选，再按用户指定的偏好排序。“优先近一点”按真实步行距离由短到长，同距离再比较耗时；“尽快到达”按真实步行耗时由短到长。用户未指定排序时，在类别和其他偏好匹配程度相近的候选中，优先步行耗时较短的地点，再比较步行距离。每条理由应指出与用户需求的具体联系。
- 安静程度、当前营业状态、实时排队等只有工具明确提供相关证据时才能陈述。没有信息时写“未核实”；地点类别和营业时间表不能直接证明现场安静、当前营业或无需排队。若用户将此类属性列为必须满足而工具无法核实，明确说明该硬条件尚不能确认，不能声称完全符合。
- 输出简短推荐列表或表格，每项包含：**地点名称、地址、步行距离、步行时间、推荐理由**。单位明确；耗时可同时写分钟和秒，或采用向上取整的分钟展示。推荐是从同一起点出发的独立选择。
- 地址等展示信息缺失时标注“高德未提供”，不补写猜测。需要说明的未核实属性紧邻对应理由，避免将推断写成事实。
- 合格结果少于输出上限时，只返回实际合格数量，简述不足原因。没有合格结果时直说“未找到已核验符合条件的地点”，区分无匹配、路线超限、属性无法核实与工具失败；可给出放宽条件的建议，不能自行放宽后冒充达标。
- 搜索或步行工具不可用、持续报错时，说明本次无法完成哪一部分验证。完成情况以实际工具结果为准，不输出虚构地点或未核验的距离和时间。
