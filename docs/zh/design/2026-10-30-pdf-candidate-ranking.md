# PDF 文档编号与正文候选排序

`document_id` 是调用方提供的非空标识符，不保证包含公司名称。检索不能因为另一个文档编号碰巧出现在问题中，就删除正确正文；也不能把所有编号中的词从正文查询中删除或统一降权。

`search_pdf_pages` 在当前 scoped Memory 的全部 PDF 页面上统计词频并排序。页面须包含查询中的正文词项才能进入候选。正文中的公司名、财务词与其他查询词使用相同的词频评分规则；同一个词是否也出现在某个文档编号中，不改变它的查询资格或正文权重。

文档编号作为独立短字段参加词项评分，每个词最多贡献一次。正文词频先按页长归一化，再与短字段的词频合并，最后使用 BM25 的饱和公式。词项的文档频率按每页正文与编号的并集统计。同一个常见财务词不会因为碰巧成为编号就获得整道问题的额外分数；编号中的名称也不会因相关页较长而一起受到正文长度惩罚。

名称空格与标点差异沿用规范化匹配。对于连写名称，只从编号实际匹配到的问题片段补充分词，不引入公司词表或别名库。正文完全不匹配的页面仍不会仅凭编号进入候选。

报表候选按“文档编号、问题要求的报表类别”分组。文档按其最高查询分数排序，每组先保留一页，再轮取第二页以容纳续表，避免另一家公司重复的报表占满某一类别的保留名额。该分组只使用文档身份，不要求编号具有公司语义。最终仍受 `limit` 限制，剩余名额按普通排序与多样性选择填充。

公开 Memory 全文搜索信号、结果去重与精确引用继续保留。接口、PDF 解析、Source 身份、存储方式和依赖保持原样。

## 回归边界

真实 Runtime 测试覆盖以下行为：

- 两份正文和问题不变，仅将无关文档编号从 `report-b` 改成 `revenue`，正确页仍能被找到。
- 问题只有 `revenue` 或 `total`，且文档编号与该词相同，正文词仍可检索。
- 比较两家公司时，正文明确给出的简称不会因不等于完整文档编号而被排除。
- 目标页面面对 60 个其他公司的重复词页面，仍进入前列；正文提供公司名称而编号不含名称的情况同样覆盖。
- 目标页扩至 116 或 516 词，仍不会被 60 个短干扰页全部挤出；编号为 `revenue` 且正文提到收入的竞争页也不能挤掉含目标公司证据的页。
- 多份报告同时存在时，问题所需的目标报告利润表和现金流量表都能被召回，不因其他报告占满全局报表候选而漏页。
- 应收款、存货或应付款与收入组成跨表比率时，通用科目映射保留资产负债表和利润表，不依赖具体公司或问题答案。
- 返回引用经持久化、重开 Runtime 和 `memory.get` 回查，核对正文投影、三字段 metadata 及完整页面身份去重。

自写测试只约束这些可观察行为，不额外要求结果只能属于某个文档编号。官方题面规定的是不同页、精确引用、上限和召回门槛，没有要求按编号排除其余所有页面。
