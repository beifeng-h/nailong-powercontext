# 财报复合问题的报表覆盖

财务问题可能明确要求同时使用利润表和现金流量表。仅把问题词项与通用财务扩展词加总，会让讨论这些概念的管理层分析页面排在真正报表前面。相同公司内的词项竞争也会发生，按公司过滤不能解决。

`search_pdf_pages` 保留现有公司范围、BM25、公开 Memory 全文信号和多样性排序。问题明确提及 income statement、statement of earnings/operations、cash flow statement、balance sheet 或相应常见表达时，另外建立这些报表类型的覆盖要求。未明确提及报表来源的问题沿用普通排序。

候选必须在正文开头的独立标题行匹配对应报表类型；支持常见 consolidated/condensed 等修饰、单复数、Profit and Loss/P&L、Cash-Flow 等同义标题、最多三行换行标题及 continued/unaudited 标记。句子中提及报表、目录行附带页码或其他说明不会仅凭关键词成为报表候选。识别只使用已存原文，没有固定公司、问题或页码。

每个明确要求的报表类型按原有分数取最多两页，先轮流保留每种类型一页，再补充第二页，以容纳续表。余下名额交给原有普通选择。所有条目来自当前 scope 的真实 Memory 引用，按 Source 身份去重，最终仍服从调用方 limit；名额不足时按问题中首次提及报表的顺序分配。

补充回归在真实 Runtime 中持久化并重开一份 53 页合成报告：两页真正报表、21 页重复财务关键词的讨论、30 页普通财务背景。原排序的 Top20 全为讨论页；修复后的显式双报表问题必须返回两页真实引用，并检查返回上限。另覆盖换行及续表标题、资产负债表与现金流的联合要求。既有公司、scope、无关问题与引用测试继续保留。

该对照验证已复现的复合问题覆盖缺陷。没有读取 FinanceBench 答案、证据或标注页，公开 PDF 的独立原文检查也不等同正式 evidence-page Recall；正式质量仍由平台核验。

## 固定环境验证

2026-10-30，在 Python 3.12.3、pypdf 6.19.0 和官方固定依赖的云端环境，解析与检索共 28 项补充测试在旧实现出现 7 项失败，修复后全部通过，无错误或跳过。PDF 公开 6 项、CSV 回归 17 项及 Pi 回归 15 项也全部通过。

产品改动限于两个 PDF 模块，官方判题资产和其他题实现未改。完整仓库 lint、类型检查未运行；本机完成 AST 和 Git 空白检查。正式评分仍需使用新提交重新提测，不能将这些回归结果当成完整语料 Recall 门槛已经通过。
