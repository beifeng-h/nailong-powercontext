# PDF 显式 Identity 流的解析

固定 pypdf 6.19 的 Crypt 解码分支拒绝带 `/Name` 或 `/Type` 的参数。合法空密码 PDF 可以显式声明 `/Crypt` 的 `/Name /Identity`，表示该流不加密。独立校验内容流时，这类合法页面会在全文解析前失败；有文字的 Identity 流也不能用空白页替代。

根据 [ISO 32000-1](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf) 的 7.4.10，Crypt 必须是过滤链的第一项，Identity 为透传过滤器。流字典中多项过滤器的参数按位置对应；字典中的 null 值等同省略键，因此缺省或 null 的 Crypt Name 按 Identity 处理。

## 解密与解码边界

使用本次解析专属的 Reader 子类，在流进入原生解密器前识别显式 Identity。只有该流的原始 payload 绕过文档的默认流密码；流字典中的字符串仍交给原生字符串密码处理。普通流完全委托原解密器，Reader 在成功和异常路径均恢复原 encryption 对象，不修改全局 pypdf 解码器或类。

随后移除 Identity 的 no-op 过滤器及其对应参数，保留剩余过滤链和参数顺序，继续原生解码和原有完整性校验。仅有 Identity 的流保留显式空过滤器数组，由原生解码器返回实际原始内容，避免 EncodedStreamObject 对省略过滤器的处理错误。

不能只在解码失败后删除 `/Name`：文档默认使用 AES 时，原生解密阶段可能已经错误处理了本应明文的 Identity 流。也不能捕获任意异常后返回空页，否则会接受损坏的压缩内容。

原始输入字节、整份 PDF 摘要、文档身份、物理页边界和 Source 协议保持原有行为。非空密码、无法支持的非 Identity Crypt 过滤器以及损坏过滤链继续以 `ValueError` 原子失败；这项适配不宣称支持全部 PDF 加密方案。

## 验证要求

独立夹具使用原生 Writer 生成 AES-128 文档，逐对象核对普通流实际加密、显式 Identity payload 为明文、流字典字符串仍受 StrF 加密。夹具不调用产品的 Identity 规范化逻辑。

十四项公共解析回归覆盖全局 Identity 空白页、普通 AES 控制、带文字的显式 Identity、后接 Flate、缺省 Name、间接参数数组和字典、null Name/Type，以及截断压缩流、非空密码、非 Identity、Crypt 非首项、重复 Crypt 和缺失参数等拒绝场景。正文、物理页顺序和原始 PDF SHA-256 均直接核对。

固定依赖环境还需重跑原有 PDF 回归和公开 PDF 测试，并对五份原件的 1258 个物理页比较修复前后完整正文和投影哈希，检查重开后的真实 Memory 与引用及已有人工诊断问题。人工问题已用于开发，不能称为官方评分或盲测。正式零分不披露失败维度，不能把这个已复现的解析缺陷直接认定为唯一正式原因。
