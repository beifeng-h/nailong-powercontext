# Taskboard state filtering — version 2

Specification ID: TASKBOARD-STATE-FILTER. Logical source key: taskboard/state-filter. This version supersedes version 1 when re-imported as the active specification.

`list_tasks(tasks, state=None)` accepts an ordered list of task mappings with string `id`, `title`, and `state`. State labels are extensible nonempty strings already in canonical form: no leading/trailing Python `str.strip` whitespace and equal to their own Python `str.casefold` value. The supplied fixture uses `open`, `done`, and the custom label `strasse`. State labels are not a closed enum.

Requested change: for a string filter, remove leading and trailing whitespace using Python `str.strip` semantics, then apply Python `str.casefold` Unicode case folding before comparing it to the stored canonical state. Normalize only the filter; do not modify stored task values.

Declared target examples against fixtures/tasks.json:

- ` OPEN ` matches task IDs `30`, `20` in that order.
- `DoNe` matches task ID `10`.
- `Straße` matches task ID `40` whose canonical state is `strasse`. This verifies Unicode case folding; ordinary lowercase alone is insufficient for this example.

Required unchanged behavior:

- `state is None` is the sole no-filter sentinel and returns all records in their original order.
- Canonical exact filters still match the same records.
- Unknown filters return an empty list. Empty or whitespace-only filters also return empty because fixture states are nonempty canonical values.
- Preserve record order, every field, and the input list/mapping contents.
- An empty task list returns an empty list.

Non-string filters other than None, missing record fields, invalid state storage, Unicode NFC/NFKC transformation, sorting, and deep-copy guarantees are outside this sample contract. Do not add unrelated validation or behavior.

The target and regression tests in tests/test_taskboard.py must remain unchanged for the before/after comparison. Only the taskboard business implementation is to be modified by the actual MiniMax development step.
